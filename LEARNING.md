# Furniro: що вивчати на цьому проєкті

## Збереження товару

1. `src/js/cards.js` створює спільні картки для Home і Shop. Кнопка має `data-save-product` з ID товару.
2. `src/js/wishlist-ui.js` обробляє кліки через **делегування подій**: один слухач на `document` працює навіть після сортування й пагінації.
3. `src/js/wishlist-store.js` змінює масив ID, записує його в `localStorage` і запускає подію `wishlist:change`.
4. Панель у хедері, лічильник і кнопки Save оновлюються з одного стану. `aria-pressed` повідомляє стан кнопки допоміжним технологіям.

Практика: зміни напис Save; збережи товар на Home; відкрий Shop і сторінку товару; перезавантаж сторінку; видали товар через серце.

## Адаптивність

- Адаптив кожного блоку знаходиться в його власному файлі: `_header.scss`, `_hero.scss`, `_footer.scss`, `_product.scss` тощо. Це дозволяє бачити базові стилі та їхні медіазапити поруч.
- `_products.scss` керує сіткою **і Home, і Shop**. Не додавай окреме правило колонок у `_shop.scss`: дві незалежні сітки знову почнуть відрізнятися.
- `_enhancements.scss` містить появу блоків, невеликі ефекти та панель обраного; `_store.scss` — кошик, пошук і повідомлення.
- `src/scss/layout/_editorial.scss`: нові About і Contact.
- `minmax(0, 1fr)` дозволяє колонці сітки звужуватися, коли всередині є довгий текст.
- `min-width: 0` прибирає небажану мінімальну ширину елементів flex/grid.
- `clamp()` плавно змінює шрифти й відступи між мінімумом та максимумом.

Практика: у DevTools перевір ширини **320, 375, 480, 540, 768, 900, 1024 і 1440 px**. Стеж за горизонтальною прокруткою, доступністю кнопок, довгими цінами та шириною полів форми. Особливо перевір 899/901 px — межу мобільного меню.

Картки мають 4 колонки на широкому екрані, 3 до 1024 px, 2 до 768 px та 1 до 480 px. На телефоні кнопки розміщені під зображенням. Медіазапит `(hover: none)` також показує їх постійно на сенсорному планшеті, навіть якщо його екран широкий. Ховер на комп'ютері та `:focus-within` для клавіатури відкривають кнопки поверх фото.

Не виправляй переповнення через `overflow-x: hidden` на всій сторінці: так можна приховати обрізані кнопки. Знайди блок, який не звужується, і виправ його ширину або сітку.

## Поява під час прокручування

`src/js/reveal.js` використовує `IntersectionObserver`: блок з атрибутом `data-reveal` отримує клас `is-revealed`, коли входить у видиму область. Після появи спостереження припиняється. Ефект працює один раз.

Перший екран залишається видимим одразу. Без підтримки API або з увімкненим `prefers-reduced-motion` контент також одразу видимий. Перехід клавішею Tab до прихованого блоку відкриває його.

Практика: додай `data-reveal` до власного блоку й зміни `translateY(12px)` у SCSS на `8px`.

## Форма й сторінки

Contact перевіряє обов’язкові поля та зберігає повідомлення локально. Реального надсилання листів немає: для нього потрібен сервер або сервіс форм. Дані контакту — демонстраційні.

Основна сторінка бренду — `about.html`; `abaut.html` також відкриває цей контент, як у запиті. При майбутніх змінах контенту онови обидва файли.

## Перевірки

```sh
npm run lint
npm run lint:styles
npm test
npm run test:build
npm run test:browser
```

DOM-тести перевіряють стан кошика, збережених товарів, пошук, форму та логіку ефектів. `test:build` перевіряє завантаження шести зібраних сторінок і шляхи зображень.

`test:browser` запускає Playwright на **production-збірці**, вимірює сторінки на восьми ширинах, перевіряє ховер, сенсорні кнопки, навігацію, фільтри, збереження після перезавантаження, кошик, вирівнювання слайдера, галерею та анімації. Скриншоти лежать у `test-results/`, звіт — у `playwright-report/index.html`.

На цьому Mac тести використовують встановлений Google Chrome. На іншому комп'ютері можна виконати `npx playwright install chromium` або задати шлях до Chrome через змінну `PLAYWRIGHT_CHROME_PATH`. Браузерні тести перевіряють Chromium; Safari та Firefox потребують окремого прогону.

Як читати помилку тесту: перевір назву сторінки та ширину, відкрий скриншот у звіті, знайди відповідний SCSS-файл, виправ правило і повтори потрібний тест. Наприклад: `npm run test:browser -- --grep "fits 375px"`.

## Слайдер і галерея на головній

У `src/js/roms.js` перемикання використовує фактичні `offsetLeft` слайдів. Тому після зміни ширини екрана не треба вгадувати ширину картки чи відступ у JavaScript. `ResizeObserver` вирівнює поточний слайд після зміни розмірів.

CSS `scroll-snap-type` у `_inspiration.scss` зупиняє прокрутку на початку слайда. Свайп працює через звичайну прокрутку браузера; обробник `scroll` синхронізує крапки та лічильник. Автоматичного перегортання немає, щоб користувач міг спокійно читати.

`src/js/gallery.js` відкриває фото в нативному `dialog`. Галерея показує всі сім фото на телефоні. Спробуй керувати стрілками клавіатури, закрити перегляд через Escape та перевірити, що фокус повертається до фото.
